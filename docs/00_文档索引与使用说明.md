# 文档索引与使用说明

**项目名称**：EEG-EmoStudio 脑电情绪识别数据制备与模型训练工作台  
**文档版本**：V1.0（基线版）  
**编制日期**：2026-11-07  
**适用对象**：软件工程本科毕业设计评审教师、指导教师、课题组成员、后续维护者

---

## 1. 这套文档解决什么问题

EEG 情绪识别毕业设计常见两种失衡：

- **只做算法**：数据集来路不清、标签不可追溯、划分有泄漏，论文结果无法复现；
- **只做软件**：需求、设计、测试与论文脱节，系统像“脚本集合”，达不到毕业设计的工程规范。

本项目把“数据制备”和“模型训练”视为同一个软件系统的两个业务域，用统一的需求编号、数据字典、测试用例和配置清单把它们串起来。文档不是事后补写的说明书，而是开发过程的基线：需求变更要回到本索引登记，设计与测试要能追溯到需求。

## 2. 推荐阅读顺序

### 2.1 评审教师 / 答辩委员会

1. `01_可行性研究报告`：选题价值、技术路线、风险；
2. `02_软件需求规格说明书`：系统边界与验收标准；
3. `05_数据审计报告`：真实数据到底有什么、缺什么；
4. `06_概要设计说明书` + `07_详细设计说明书`：工程实现是否自洽；
5. `09_测试计划与验收标准`：证据链是否闭合；
6. `12_毕业设计符合性矩阵`：是否满足毕业设计要求；
7. `15_Web系统设计与使用说明`：前后端、页面与 API；
8. `16_SEED_IV数据接入报告`：真实数据、基线结果与边界；
9. `17_实验采集与EEG预处理说明`：视频问卷、EEGLAB 清洗与对齐。

### 2.2 课题组成员 / 后续维护者

1. `README.md`：快速运行；
2. `10_用户手册`：命令、数据契约、故障处理；
3. `08_数据字典与数据治理规范`：字段含义与质量门禁；
4. `13_配置管理与质量保证计划`：提交、版本、复现规则；
5. `05_数据审计报告`：当前数据资产与待办。

### 2.3 论文写作

1. `04_文献综述与需求依据`：绪论与相关工作；
2. `11_毕业论文写作纲要`：章节结构、图表清单；
3. `05_数据审计报告` + `09_测试计划`：数据与实验章节；
4. `12_毕业设计符合性矩阵`：自检与答辩问答。

## 4. 文档与软件工程生命周期的对应

| 阶段 | 主要活动 | 产出文档 | 质量 gate |
|---|---|---|---|
| 立项 | 选题、可行性、文献 | 01、04、14 | 导师确认选题 |
| 需求 | 访谈、数据审计、用例 | 02、05、08 | 需求评审通过 |
| 设计 | 架构、模块、接口、数据 | 06、07 | 设计评审通过 |
| 实现 | 编码、单元测试、代码评审 | 代码、13 | 测试通过 + 代码评审 |
| 测试 | 集成、系统、验收 | 09 | 退出准则满足 |
| 交付 | 用户手册、论文、答辩 | 10、11、12 | 指导教师验收 |
| 维护 | 缺陷、数据版本、复现 | 13、变更记录 | 变更评审 |

> 本项目采用增量迭代：数据审计与基线流水线先跑通，再逐步接入真实 EEG、域适应与更复杂的模型。每一轮迭代都必须保留可复现的配置与数据哈希。

## 5. 编号与引用约定

- 需求：`FR-xx`（功能）、`NFR-xx`（非功能）、`DR-xx`（数据需求）、`BR-xx`（业务规则）；
- 用例：`UC-xx`；
- 测试：`TC-xx`；
- 风险：`R-xx`；
- 数据质量门禁：`QG-x`；
- 文档引用格式：`[文档编号] §章节`，例如 `[02] §3.4`。
- 需求到设计、代码、测试的追溯见 `09` 第 7 节与 `12` 第 3 节。

1. 在 `13_配置管理与质量保证计划` 的变更记录中登记；
2. 说明影响的需求编号、代码模块、测试用例；

4. 重大变更（研究问题、标签体系、评估协议）必须经指导教师确认。

## 7. 交付物形态

```text
docs/*.md                 # 可版本管理的文档源
docs/assets/*.png         # 论文/文档插图
research/                 # 研究过程资料（质量排序、文献清单、周报、历史脚本）
deliverables/*.docx       # 按学校格式排版的 Word 版
deliverables/*.xlsx       # 数据审计/选材工作簿
artifacts/audit/          # 审计证据（JSON/CSV/Markdown）
artifacts/selection/      # 选材清单与报告
artifacts/demo/           # 软件验收演示结果
```

Markdown 源是唯一事实源；DOCX 由脚本生成，避免“文档里一套数字、代码里另一套数字”。生成脚本：`scripts/build_docx.py`。
