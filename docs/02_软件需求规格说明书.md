## 1. 引言

### 1.1 目的

本文定义 EEG-EmoStudio 的功能边界、数据契约、质量规则、非功能指标与验收标准。它是设计、编码、测试和论文“系统实现”章节的共同基线。

### 1.2 产品范围

系统覆盖一条端到端链路：

```text
刺激库 → 预评价问卷 → 清洗/质量评分 → 平衡选材 → EEG 采集
      → 预处理 → DE 特征 → 数据集清单/划分 → 模型训练/跨被试评估 → 报告
```

系统**不**承担：伦理审批、设备驱动、刺激版权清理、临床诊断、在线实时 BCI 控制。

### 1.3 术语与缩略语

| 术语 | 含义 |
|---|---|
| 刺激（stimulus） | 用于诱发情绪的视频片段或音乐片段 |
| 四象限 | 效价×唤醒的 HVHA/HVLA/LVHA/LVLA 四类 |
| DE | 微分熵（Differential Entropy） |
| Trial | 一次“刺激呈现 + 生理记录 + 自评”的完整单元 |
| Session | 同一被试的一次实验会话，含多个 Trial |
| LOSO | Leave-One-Subject-Out，留一被试交叉验证 |
| UDA | 无监督域适应（Unsupervised Domain Adaptation） |
| OOF | Out-of-Fold，折外预测汇总 |
| 质量分 | 0–100 的材料可用性评分，不是情绪标签真值 |
| 泄漏 | 测试信息（被试、标签、标准化统计量）进入训练/选择过程 |

## 2. 总体描述

### 2.1 产品定位

面向单实验室、单机/小型服务器部署的科研工作台。以 CLI 与本地 Web 控制台为交互方式，以文件型数据仓库为存储，以 HTML/JSON/PNG 为证据输出。目标是让研究者“用一条命令复现一次数据审计或一次 LOSO 实验”，而不是手工拼接脚本。

### 2.2 用户类别

| 角色 | 主要诉求 | 权限 |
|---|---|---|
| 数据管理员 | 导入问卷/映射/媒体，处理异常 | 读写原始与派生数据 |
| 实验员 | 按清单准备材料、登记被试/会话 | 读写实验元数据，只读质量结果 |
| 算法工程师 | 提特征、训练、调参、导出报告 | 读写特征/模型/实验 |
| 导师/评审 | 查看报告、复现结果 | 只读 |
| 被试 | 完成实验与自评 | 不直接使用系统 |

### 2.3 运行环境

- OS：Windows 10/11 或 Linux；
- Python：3.11+（验证环境 3.12.6）；
- 依赖：NumPy、SciPy、pandas、PyTorch、Matplotlib、openpyxl；MNE 可选；
- 硬件：CPU 可完成小规模训练；GPU 可选加速；
- 存储：原始媒体约数 GB；特征/模型按实验增长；
- 显示：CLI + 浏览器查看 HTML 报告。

### 2.4 设计与实现约束

- C-01：不得移动、改名或覆盖课题组原始数据；
- C-02：所有派生数据必须可追溯到源文件与处理参数；
- C-03：被试身份伪匿名化，报告不得出现真实姓名；
- C-04：跨被试实验必须按被试隔离，禁止同被试跨集合；
- C-05：随机过程必须固定种子并记录；
- C-06：外部数据必须遵守许可证；
- C-07：单机离线可运行，不依赖云服务；
- C-08：中文文档、中文报告优先，代码标识符用英文。

### 2.5 假设与依赖

- A-01：问卷导出格式为 CSV（UTF-8 BOM），字段名可能随问卷版本变化；
- A-02：刺激材料可通过“编号/文件名”与映射表关联；
- A-03：EEG 数据可整理为 `(trials, channels, samples)` 的 NPZ；
- A-04：标签为 0-based 整数，类别名单独提供；
- A-05：SEED-IV 已接入；自采 EEG 到位前，合成数据只用于软件验收；
- A-06：学校模板与字数要求在定稿前提供。

## 3. 功能需求

> 优先级：P0 = 必须（V1.0 验收）；P1 = 应该（V1.1）；P2 = 可选。  
> 状态：已实现 / 部分实现 / 规划。

### FR-01 项目与被试管理（P0，部分实现）

**描述**：系统应支持以项目为单位管理被试、会话、Trial 与数据文件；被试使用伪匿名 ID。

**输入**：被试编号、年龄/性别（可选）、组别、知情同意状态、会话日期、设备、采样率。

**处理**：生成稳定 ID；校验必填；关联会话与 Trial；禁止姓名进入分析表。

**输出**：`subjects.csv`、`sessions.csv`、`trials.csv`（V1.1 完整实现；V1.0 以 NPZ 中的 `subjects` 字段承载）。

**验收**：同一被试跨会话 ID 一致；报告只显示伪 ID；删除被试可级联标记其数据。

### FR-02 刺激材料库管理（P0，已实现审计）

**描述**：登记视频/音乐的名称、类型、语言、字幕、时长、预设连续/离散情绪、文件路径、版权来源。

**输入**：`素材列表.xlsx`、`视频对应关系.csv`、`音乐对应关系.csv`、媒体文件。

**处理**：校验 120+120 条、四象限各 30、文件名存在、时长可解析、类别合法；报告缺失/多余/重复文件。

**输出**：材料审计表、问题清单。

**验收**：缺失文件 0、类别各 30、每条材料可定位到物理文件；异常有明确提示。

### FR-03 问卷导入与清洗（P0，已实现）

**描述**：导入问卷星 CSV，自动识别字段，规范化编号/姓名/评分/文本选项，检测重复与无效作答。

**输入**：视频/音乐问卷 CSV。

**处理**：

1. 按关键词识别 15 个业务字段；
2. 编号提取数字，应用显式别名（`388.mp4 → 38.mp4`）；
3. 姓名去除空格/间隔号；
4. 效价/唤醒统一为 1–9（含文字锚点）；
5. 同一评分者×刺激保留首次提交；
6. 计算评分者覆盖率、直线作答（效价与唤醒 SD 均 < 1.0）；
7. 解析 Q11 多选与 Q12 自由文本。

**输出**：`*_ratings_clean.csv`、`*_rater_table.csv`、`*_playback_issues.csv`、`*_survey_summary.json`。

**验收**：实际数据视频 1,269→1,227、音乐 1,087→1,072；无效评分单元 0；重复数与既有报告一致；每个异常可回溯到原始行号。

### FR-04 刺激质量评分（P0，复用既有结果）

**描述**：按 E（情绪诱发，50）+ C（一致性，20）+ L（标签效度，15）+ D（干扰控制，10）+ N（样本充分性，5）计算基础分，再乘播放问题门控 G。

**输入**：清洗后评分、目标象限、问题严重度。

**处理**：

- 计算每条刺激的均分、SD、主导情绪份额、目标象限命中率、问题指数；
- `G = exp(-3w) × (w>0 ? 0.75 : 1)`，下限 0.05；
- 输出分数、等级（S/A/B/C/D）、置信区间、稳健性检验。

**输出**：质量排序 CSV/XLSX、评分规则表、问题清单。

**验收**：视频/音乐各 120 条；等级分布与既有报告一致；权重扰动 ±20% 的 Spearman 相关 ≥ 0.95（既有结果）。

> V1.0 直接读取既有质量结果，避免重复实现 465 行评分脚本；V1.1 将评分逻辑迁入包内并加单测。

### FR-05 平衡选材（P0，已实现）

**描述**：按“模态 × 四象限”分层，优先高质量等级，输出正式实验材料清单。

**输入**：质量排序表、每类数量 N、最低等级。

**处理**：模态内按象限分组；等级 S→A→B→C→D 排序，同等级按分数降序；取前 N；不足时告警；不跨象限比较。

**输出**：`selected_materials.csv`、`selection_summary.json`、`selection_report.md`。

**验收**：80 条示例中四象限各 10 条/模态；无 C/D；每条含模态、ID、分数、等级、主要问题、选择理由。

### FR-06 EEG 原始数据导入（P0，部分实现）

**描述**：接收采集设备导出的 EEG、事件与自评，形成统一 `raw.npz`。

**输入**：设备原生格式（BrainVision/NeuroScan/Neuracle 等）、事件文件、通道位置、采样率。

**处理**：通道重命名/排序、单位换算、事件对齐、Trial 切分、质量初检。

**输出**：`raw.npz`（x/y/subjects/fs/class_names）、导入日志。

**验收**：通道数/采样率/试次数与设备记录一致；事件时间误差 ≤ 1 个采样点；缺失/重复 Trial 被拒绝。

> V1.0 实现 `raw.npz` 契约与合成数据生成；原生格式适配器为 V1.1。

### FR-07 EEG 预处理（P0，已实现核心）

**描述**：对连续/分段 EEG 进行带通、陷波、重参考、重采样、幅度伪迹剔除。

**输入**：`(trials, channels, samples)`、fs、配置。

**处理**：

- 4 阶 Butterworth 零相位带通（默认 0.1–70 Hz）；
- 50 Hz 陷波（Q=30）；
- 可选 CAR 重参考；
- 可选 `resample_poly` 重采样（默认 200 Hz）；
- 峰峰值阈值剔除（默认 150 µV）。

**输出**：预处理数组、参数记录、剔除统计。

**验收**：滤波后无 NaN/Inf；50 Hz 抑制可量化；重采样后长度符合预期；参数写入特征清单。

### FR-08 特征提取（P0，已实现）

**描述**：提取 5 频带 DE，支持滑窗与聚合。

**输入**：预处理 epoch、fs、窗口/步长。

**处理**：

- 频带：δ 1–4、θ 4–8、α 8–14、β 14–30、γ 30–45 Hz；
- 每通道/频带/窗口计算 `0.5·ln(2πeσ²)`；
- 支持 mean/std/concat 聚合。

**输出**：`features.npz`（samples×channels×bands）、构建参数 JSON。

**验收**：形状、频带数、窗口数正确；特征有限；同一输入重复运行结果一致（固定浮点环境）。

### FR-09 数据集装配与版本（P0，已实现 NPZ/清单）

**描述**：把特征、标签、被试、会话、类别名、源文件哈希组装为不可歧义的数据集版本。

**输入**：特征数组、元数据、源文件。

**处理**：校验形状/标签/缺失；计算 SHA-256；生成 manifest（样本数、通道、类别分布、被试分布、生成时间）。

**输出**：`features.npz` + `features.manifest.json`。

**验收**：manifest 可独立回答“这份数据从哪来、多少样本、多少被试、类别是否平衡”；哈希可复算。

### FR-10 数据划分（P0，已实现）

**描述**：支持 LOSO 与被试依赖两种划分，严格防泄漏。

**输入**：y、subjects、验证比例、种子。

**处理**：

- LOSO：每折留一名被试；验证集只从其余被试中分层切分；
- 被试依赖：分层随机切分 train/val/test；
- 断言 train/val 与 test 的被试集合不相交；
- 记录每折被试清单与样本数。

**输出**：`folds.json`、划分描述。

**验收**：每个测试样本恰好被留出一次；无被试重叠；固定种子可复现。

### FR-11 模型训练（P0，已实现）

**描述**：训练 MLP、DGCNN、DualView-MultiProto、EEGNet，支持类别权重、早停、检查点。

**输入**：特征/原始波形、标签、划分、配置。

**处理**：

- 训练折拟合标准化，验证/测试只 transform；
- AdamW + 余弦退火 + 梯度裁剪；
- 类别加权交叉熵；
- DualView 额外原型正则；
- 以验证损失早停并恢复最佳权重。

**输出**：每折检查点、训练历史、配置、环境信息。

**验收**：损失有限；早停生效；测试集不参与任何拟合；同配置同种子结果一致（CPU 下）。

### FR-12 跨被试域适应（P1，规划）

**描述**：在 UDA 设置下使用目标域无标签数据做特征对齐（DANN/MMD/原型对齐）。

**输入**：源域有标签、目标域无标签。

**处理**：域判别器 + 梯度反转；或 MMD/原型对比；目标域标签只用于最终评估。

**输出**：适应前后指标对比。

**验收**：目标域标签绝不进入训练；与无适应基线同划分可比。

### FR-13 评估与统计（P0，已实现）

**描述**：计算 ACC、平衡 ACC、Macro-F1、Cohen's κ、分类别 P/R/F1、混淆矩阵、95% CI、分被试结果。

**输入**：y_true、y_pred、类别数。

**处理**：OOF 汇总；bootstrap 置信区间；按被试分组统计。

**输出**：`metrics.json`、`oof_predictions.npz`、混淆矩阵图、分被试柱状图。

**验收**：指标与手算/第三方库一致（抽查）；所有测试样本只出现一次；报告含随机水平。

### FR-14 实验追踪与复现（P0，部分实现）

**描述**：每次运行记录配置、种子、环境、数据哈希、代码版本、输出路径。

**输入**：运行参数。

**处理**：生成 `run.json`；检查点命名含 fold/被试；输出目录隔离。

**输出**：可复现实验包。

**验收**：给定数据+配置+种子，可复现指标（允许浮点微小差异）；能从 manifest 追溯到源数据。

### FR-15 报告与导出（P0，已实现 HTML）

**描述**：生成中文 HTML 报告，包含摘要卡片、总体指标、分类别指标、逐折表、分被试表、混淆矩阵、配置与免责声明。

**输入**：metrics、图表、配置。

**处理**：自包含 HTML（图片 base64），无外部依赖。

**输出**：`report.html`。

**验收**：浏览器直接打开；中文无乱码；合成数据报告显著标注“非科研结论”。

### FR-16 命令行与自动化（P0，已实现）

**描述**：提供 `audit/select/demo/features/train` 子命令，返回码 0/非 0，支持脚本化。

**输入**：命令行参数。

**处理**：参数校验、错误提示、输出路径创建。

**输出**：stdout 摘要、stderr 错误、文件产物。

**验收**：`--help` 完整；非法参数返回非 0；无交互阻塞。

### FR-17 合成数据演示（P0，已实现）

**描述**：生成带被试偏移的合成特征或有节律的合成 EEG，用于软件验收与教学演示。

**输入**：被试数、每类样本数、通道/频带、种子。

**处理**：生成、保存、LOSO、报告。

**输出**：`artifacts/demo/`。

**验收**：端到端 < 10 min（CPU）；报告标注合成；不进入论文性能表。

### FR-18 审计日志与数据血缘（P1，部分实现）

**描述**：记录谁在何时对哪个数据执行了什么操作，支持回溯。

**输入**：操作、文件、参数、结果。

**处理**：追加 JSONL；文件哈希。

**输出**：`audit_log.jsonl`。

**验收**：任一派生文件可追溯到源文件与命令。

### FR-19 Web 控制台（P0，已实现）

**描述**：在 CLI 之上提供本机 Web 控制台，覆盖“工作台、数据审计、材料选材、数据集、模型训练、实验记录、项目文档、系统状态”八个页面。

**输入**：浏览器请求；表单参数；`raw.npz` 上传；任务轮询。

**处理**：

1. Jinja2 服务端渲染首屏，原生 CSS/JS 负责交互与 SVG 图表；
2. `POST /api/{audit|selection|features|train}/run` 创建后台任务；
3. `GET /api/jobs/{id}` 返回状态与日志，前端 1.4 s 轮询；
4. 训练/特征任务调用现有 CLI 子进程，不复制算法；
5. 文件下载使用白名单，防止路径遍历；
6. 默认仅监听 `127.0.0.1`。

**输出**：8 个页面、JSON API、任务控制台、DOCX/PDF/CSV 下载、ZIP 打包。

**验收**：所有页面均 200；审计/选材/训练/上传/特征任务可成功；报告/图表可打开；58 项测试通过；页面不出现真实姓名。

## 4. 外部接口需求

### 4.1 用户接口

- CLI：`python -m eeg_emostudio <command> [options]`；
- 报告：HTML5，兼容 Edge/Chrome；
- 文档：Markdown + DOCX；
- 错误信息：中文、可操作（指出文件/字段/修复建议）。

### 4.2 软件接口

| 接口 | 方向 | 格式 | 说明 |
|---|---|---|---|
| 问卷 CSV | 入 | UTF-8 BOM | 问卷星导出 |
| 映射 CSV | 入 | UTF-8 BOM | 编号/文件名/类别 |
| 质量 CSV | 入 | UTF-8 BOM | 既有排序结果 |
| 媒体文件 | 入 | MP4/MP3 | 只读 |
| raw.npz | 入 | NPZ | x/y/subjects/fs |
| features.npz | 入/出 | NPZ | x/y/subjects/sessions/class_names |
| manifest.json | 出 | JSON | 数据版本与哈希 |
| metrics.json | 出 | JSON | 指标与配置 |
| report.html | 出 | HTML | 自包含 |

### 4.3 硬件接口

- EEG 放大器：通过厂商软件导出，V1.0 不直接驱动；
- 视频播放：实验程序负责，系统只提供材料清单；
- 存储：本地 NTFS/ext4，建议 SSD。

### 4.4 通信接口

V1.0 无网络通信；如需多机协作，通过共享目录/对象存储同步，禁止公网明文传输可识别数据。

## 6. 数据需求

### 6.1 数据实体

被试、会话、Trial、刺激、评分、质量分、特征集、划分、实验、模型、报告。

### 6.2 数据量

| 数据 | 当前 | 目标 |
|---|---|---|
| 刺激 | 240 | 240（或扩充） |
| 预评价 | 2,356 条原始 | 保持/扩充 |
| 被试 | 0（EEG） | ≥30（跨被试） |
| Session | 0 | 每人 1–3 |
| Trial | 0 | 每人 40–80 |
| 特征样本 | 合成 960 | 真实 ≥2,400 |

### 6.3 数据质量

- 完整性：必填字段缺失率 < 1%；
- 唯一性：同一评分者×刺激无重复；
- 一致性：编号/类别/文件名三方一致；
- 有效性：评分 1–9，类别在允许集合；
- 时效性：问卷提交时间在采集窗口内；
- 可追溯性：每个派生文件有 SHA-256 与参数。

### 6.4 数据保留与销毁

- 原始数据保留至论文答辩后 3 年（或按学校要求）；
- 脱敏数据可长期保存；
- 被试撤回时，删除可识别信息并标记其数据不可用于新研究；
- 备份加密，访问留痕。

## 7. 业务规则

| 编号 | 规则 | 理由 |
|---|---|---|
| BR-01 | 视频 `388.mp4` 仅映射为 `38.mp4`，不做通用取模 | 避免误改其他编号 |
| BR-02 | 同一评分者×刺激保留首次提交 | 防止重复提交放大权重 |
| BR-03 | 效价/唤醒文字锚点映射为 1/9 | 与 9 点量表一致 |
| BR-04 | 直线作答：效价与唤醒 SD 均 < 1.0 | 识别不认真作答 |
| BR-05 | 播放问题严重度按 `1-∏(1-p)` 并集 | 多选问题不应简单相加 |
| BR-06 | 选材不跨象限比较 | 防止 HVHA 垄断 |
| BR-07 | 测试被试不参与标准化/早停/调参 | 防止泄漏 |
| BR-08 | 验证集只从训练被试切分 | LOSO 诚实评估 |
| BR-09 | 类别不平衡用加权损失，不重采样测试集 | 保持评估分布 |
| BR-10 | 合成数据不得进入论文性能表 | 防止误导 |
| BR-11 | 质量分不得替代被试自评标签 | 质量≠情绪真值 |
| BR-12 | 任何标签体系变更需版本化 | 防止混用 |

## 8. 典型用例

### UC-01 审计一批新问卷

**参与者**：数据管理员。  
**前置**：问卷 CSV 已导出。  
**主流程**：

1. 运行 `audit`；
2. 系统识别字段、清洗、统计；
3. 管理员查看 `audit_report.md` 与问题 CSV；
4. 对无法自动处理的记录人工复核并登记。

**异常**：字段缺失 → 报错并列出实际列名；编码错误 → 提示使用 UTF-8 BOM。  
**后置**：生成清洗数据与审计证据。

### UC-02 选择正式实验材料

**参与者**：实验员。  
**前置**：质量排序已生成。  
**主流程**：

1. 设定每类数量与最低等级；
2. 运行 `select`；
3. 查看分层报告与警告；
4. 按清单准备媒体，核对时长/播放。

**异常**：某层不足 → 警告并建议放宽等级或补充材料。  
**后置**：`selected_materials.csv`。

### UC-03 从原始 EEG 构建特征集

**参与者**：算法工程师。  
**前置**：`raw.npz` 符合契约。  
**主流程**：

1. 运行 `features`；
2. 检查形状、频带、窗口；
3. 查看构建参数与 manifest。

**异常**：NaN/形状不符 → 拒绝并指出样本。  
**后置**：`features.npz` + manifest。

### UC-04 训练并评估跨被试模型

**参与者**：算法工程师。  
**前置**：特征集与类别名。  
**主流程**：

1. 运行 `train --setting loso`；
2. 系统逐折训练、早停、预测；
3. 汇总 OOF 指标与置信区间；
4. 生成 HTML 报告与检查点。

**异常**：某折样本不足 → 明确报错；CUDA 不可用 → 回退 CPU 或报错。  
**后置**：`metrics.json`、`report.html`、`checkpoints/`。

### UC-05 复现论文表格

**参与者**：评审/后续学生。  
**前置**：拿到数据 manifest、配置、代码版本。  
**主流程**：

1. 校验 SHA-256；
2. 按配置运行；
3. 对比指标与论文表格；
4. 记录差异。

**后置**：复现记录。

### UC-06 合成数据软件验收

**参与者**：开发者/评审。  
**主流程**：`demo` → 查看报告 → 确认标注“合成”。  
**后置**：验收证据。
