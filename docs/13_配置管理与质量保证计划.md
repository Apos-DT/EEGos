# 配置管理与质量保证计划

**项目**：EEG-EmoStudio 脑电情绪识别数据制备与模型训练工作台  
**文档编号**：13  
**版本**：V1.0  
**日期**：2026-11-07

---

## 1. 目的

保证代码、数据、文档、实验产物的版本一致，任何论文数字都能追溯到“哪份数据 + 哪份代码 + 哪组参数 + 哪个种子”。

## 2. 配置项

| 类别 | 配置项 | 位置 | 版本方式 |
|---|---|---|---|
| 代码 | Python 包/测试/脚本 | `eeg_emostudio/`、`tests/`、`scripts/` | Git commit |
| 文档 | 00–14 文档 | `docs/` | Git + 文档版本号 |

| 划分 | folds.json | 实验目录 | seed + 文件哈希 |
| 模型 | checkpoints | 实验目录 | fold + 配置 |
| 指标 | metrics.json | 实验目录 | run_id |
| 图表 | PNG/HTML | 实验目录 | 同 run_id |
| 报告 | DOCX/PPTX | `deliverables/` | 版本号 |

**原则**：原始数据/大文件不进 Git；用 `.gitignore` 排除 `artifacts/`、`*.npz`、`*.pt`、媒体。

## 3. 版本规则

### 3.1 代码

语义化版本 `MAJOR.MINOR.PATCH`：

- MAJOR：契约不兼容（npz 字段/标签编码/划分语义）；
- MINOR：新增功能（模型/命令）；
- PATCH：修复/文档。

### 3.2 数据

`{modality}_v{major}.{minor}` + manifest 哈希：

```text
features_selfcollected_v1.0.npz
features_selfcollected_v1.0.manifest.json
```

任何字段/预处理变更 → minor+1；标签体系变更 → major+1。

### 3.3 实验

```text
{date}_{model}_{setting}_seed{seed}_{short_hash}
20261107_dualview_loso_seed42_a1b2c3d
```

## 4. Git 工作流

### 4.1 分支

- `main`：可交付/可复现；
- `dev`：日常开发；
- `feat/<name>`：新功能；
- `fix/<name>`：修复；
- `docs/<name>`：文档。

### 4.2 提交信息

```text
feat(audit): support music mapping duration outliers
fix(splits): prevent validation subject leakage
docs(srs): add acceptance criteria for FR-13
test(models): add dualview prototype loss test
```

### 4.3 合并前检查

- [ ] 全部测试通过；
- [ ] 新增/修改有测试；
- [ ] 无硬编码绝对路径；
- [ ] 无真实姓名/密钥；
- [ ] 文档同步；
- [ ] `demo` 可跑；
- [ ] 代码评审通过。

### 4.4 标签

```text
v0.1.0   首个可运行原型
v0.2.0   真实数据接入
v1.0.0   毕业设计交付
```

## 5. 代码评审清单

| 维度 | 检查 |
|---|---|
| 正确性 | 边界/空值/形状/单位 |
| 泄漏 | 标准化/早停/调参是否只用训练折 |
| 可复现 | 种子/配置/环境/哈希 |
| 可读性 | 命名/注释/函数长度 |
| 异常 | 错误信息是否可操作 |
| 性能 | 是否有明显 O(n²)/重复计算 |
| 安全 | 姓名/IP/路径/密钥 |
| 测试 | 新增分支是否覆盖 |

## 7. 可复现性规范

每次论文实验必须保存：

1. 代码 commit；
2. 数据 manifest + SHA-256；
3. 配置文件/CLI 命令；
4. 随机种子；
5. Python/PyTorch/NumPy 版本；
6. 硬件（CPU/GPU）；
7. 输出 `metrics.json`；
8. 运行日期/执行人。

**复现判定**：同一环境重跑，ACC 差异 ≤0.5 个百分点；若超过，分析原因（非确定性/数据变更/依赖升级）。

## 8. 数据备份与恢复

### 8.1 3-2-1 原则

- 3 份副本；
- 2 种介质（SSD + 移动硬盘/NAS）；
- 1 份异地/离线。

### 8.2 周期

- 原始数据：采集当日备份；
- 特征/模型：每次冻结后备份；
- 文档：每日 Git；
- 每周抽检哈希。

### 8.3 恢复演练

每 4 周随机抽取 1 个实验包，在另一目录恢复并重跑指标；记录差异。

---

## 9. 文档控制

- Markdown 是源，DOCX 是导出；
- 每份文档有编号/版本/日期/状态；
- 变更记录在文档末尾；
- 数字必须与 JSON/CSV 一致；
- 图表文件名稳定，避免“最终版/最终版2”；
- 论文定稿后冻结文档，不再改数字。

## 10. 风险与质量记录

| 风险 | 质量影响 | 控制 |
|---|---|---|
| 数据泄漏 | 结果虚高 | 断言 + 评审 + 复核 |
| 标签混用 | 结论错误 | 数据字典 + 版本 |
| 合成数据误用 | 学术不端 | 报告显著标注 + 检查清单 |
| 依赖升级 | 结果变化 | 锁定版本 + 复现测试 |
| 硬盘故障 | 数据丢失 | 3-2-1 + 哈希 |
| 文档不同步 | 答辩质疑 | 单一事实源 + 自动导出 |
